Task CS[18] migrates about 1,560 times per second. Its average time on each core is about 0.5 milliseconds, and its ping-pong count is high. This is migration thrashing, but it does not by itself prove lock contention. Common causes include task affinity or too many similar worker tasks. A lock bounce is different: it occurs when a task moves to another core while it still owns a lock.
