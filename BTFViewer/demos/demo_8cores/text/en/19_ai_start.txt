When the log is empty, select Start Investigation. This runs Auto investigate for the highest-ranked Analysis finding. For your first investigation, use the built-in prompt templates instead of a long free-form question.

This example uses gemini-3.1-flash-lite. It took about 20 seconds, used about 128,800 tokens, and called 11 tools. Your result will be different.

The selected finding is Priority Inversion on task PS[228]. It matches the Low, Medium, and High pattern that we checked earlier.

The tool cards investigate the finding, detect priority inversion, query Priority Inheritance, set cursors from 3,055,033 to 3,055,153, zoom the view, and highlight PS[228]. The investigation also checks the critical path near 3,055,093, builds a task dependency graph, estimates a shorter critical section with What-if, and adds a bookmark. If Auto-apply is off, select Apply for each action that should change the timeline.

Read the reply in three parts. First, check the conclusion and its confidence. Second, follow the causal chain through each jump:TIME link. Third, review the task dependencies and alternative explanations. In this example, the evidence includes a priority boost from 2 to 4, a migration from Core 7 to Core 6, and shared-lock relationships with CS tasks.

The Evidence panel is created by BTFViewer, not by the model. It lists the current issue, tool reasons, evidence quality, cost, and conditions that could disprove the conclusion. Click every jump:TIME link. Then check Priority Inheritance, Mutex Blocking, Critical Path, and the red boost bar on the timeline. Even if the model reports High confidence, verify the evidence yourself. Treat What-if as an estimate only.

This is the beginner workflow: start from a named finding, follow the evidence to the timeline, and confirm or reject the explanation in Statistics. A later run may select a different finding.
